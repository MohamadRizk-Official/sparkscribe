# SparkScribe authentication

How sign-in works, what each email link may do, and where the code is. Supabase Auth (one project,
`strkrrdndoofpcenopxk`, shared by Preview and Production) with the PKCE flow in the browser; static pages on Vercel.

Related: `INVESTIGATION-2026-10-16.md` (why this was reworked), `EMAIL-SETUP.md` (Resend, DNS, templates),
`RELEASE.md` (tests, rollout, rollback, CAPTCHA activation).

## Concepts kept separate

| Concept | Where it is decided |
|---|---|
| **Email ownership** | Supabase: an email/password account gets no session until its address is confirmed (`mailer_autoconfirm: false`). Google accounts come verified by Google. |
| **Authentication** (who you are) | Supabase session in this browser (`sb-<ref>-auth-token`), checked with the server by `getUser()` before private pages. |
| **Authorization** (what you may read/write) | Row Level Security in Postgres (per user); the AI API verifies the token with Supabase on every call (`server/http.js`). |
| **Reset session** | A session whose newest `amr` method is `recovery`. Only for choosing a new password (below). |
| **Age / Terms** | Not collected in Production yet. It ships with the approved legal pages (owner decision 2026-10-16). |

## Flows

### Password reset
```
Forgot password (email + Turnstile token) ──► Supabase sends the reset email
   │
   ▼  link: /auth/callback#token_hash=…&type=recovery   (old emails: Supabase /verify → /auth/callback?code=…)
Callback page: "Reset your password" [Continue]   ◄── nothing is used until the press (mail scanners can't use it up)
   │ verifyOtp(recovery) → reset session (amr: recovery)
   ▼
/auth?mode=update  "Choose a new password" (no account menu, no Turnstile, "Cancel and return to sign in")
   │ updateUser({ password })  — refused: same / weak / expired → message, form stays or asks for a new link
   ▼
signOut(global) → this browser signed out (local fallbacks if the network fails)
   ▼
/auth  "Password updated successfully. Please sign in with your new password."  (email filled in, history replaced)
   ▼
Normal sign-in (+ Turnstile) → app
```
While a reset session exists (`src/lib/recovery.js`):
* on `/auth?mode=update`, within **15 minutes of opening the link**, it may set a password. This is a form-filling window
  that starts when the link is opened. It is separate from the link's own lifetime (Supabase → Auth → Email OTP
  expiration), which decides whether the link opens at all.
* any other page: fresh → sent back to the form; older → signed out in this browser (`guardRecovery`, called by
  `requireUser` and the account menu on every page);
* `/auth` without `mode=update`: signed out there;
* the API refuses it: `403 recovery_session` (`server/http.js`, `isRecoveryToken`).

The 15-minute window is a UX and safety choice: a forgotten tab can't change the password later. Whoever holds a
valid reset link can always set a password; the restriction is about not entering the app by accident.

### Sign-up and email verification
```
Create account (email, password, Turnstile) → "Check you@… for a link to verify your email address, then sign in."
   │                                            [Send the link again] (Turnstile)
   ▼  link: /auth/callback#token_hash=…&type=email   (old emails: …/auth/callback?code=…&flow=signup)
Callback: "Verify your email address" [Verify Email Address]
   │ verifyOtp in a separate in-memory client → confirmed → that session is signed out at once
   ▼
/auth  "Email verified. Please sign in to start using SparkScribe."  (email filled in)
   ▼
Sign in → app
```
If another account is signed in on that browser, it is left alone and the page says which account is signed in.
Signing in before confirming: "Please confirm your email first" + [Send the link again].

### Google
`signInWithOAuth` → Google → Supabase → `/auth/callback?code=…` → signed in → `next`. No Turnstile (Supabase doesn't
check CAPTCHA on OAuth).

### Redirect safety
Every `next` goes through `safeNext` (`src/lib/account.js`): same-origin paths only. Control characters and backslashes
are rejected, then the URL parser decides the origin. The callback shows only known error codes, in our words, and
never text from the link. The sign-in page shows only known Supabase errors; anything else becomes "Something went
wrong. Please try again."

## Email links
* Templates: `docs/auth/email-templates/*.html`, generated by `node scripts/build-email-templates.mjs`.
* Link format: `https://www.spark-scribe.com/auth/callback#token_hash={{ .TokenHash }}&type=<type>`, with types
  `email` (sign-up), `recovery`, `magiclink`, `invite`, `email_change`. All are accepted by the live server (verified
  2026-10-16 with an invalid token: 403 `otp_expired`; an unknown type → 400).
* The token is in the **fragment**: it never reaches Vercel or any server log, and the page sets
  `referrer=no-referrer`. After the press the address is replaced with `/auth/callback`.
* Old `{{ .ConfirmationURL }}` links (sent before the template switch) keep working in the browser that asked for them.

## Cloudflare Turnstile
`src/lib/captcha.js`. Managed widget, `interaction-only`. One fresh token per request on: password sign-in, sign-up,
reset email, resend confirmation. Not used on: Google, setting a new password, the callback.
**Fails open**: if the widget can't produce a token, the request is sent without one and Supabase decides. While
Supabase CAPTCHA protection is off, nobody is locked out by a widget problem.
* Site Key (public): Vercel `VITE_TURNSTILE_SITE_KEY` (Config type) for Production, and Preview scoped to
  `release/four-tier` and `release/auth`.
* Secret Key: **only** in Supabase → Authentication → Attack Protection (entered by the owner).
* Widget hostnames (Cloudflare): `spark-scribe.com`, `www.spark-scribe.com`,
  `sparkscribe-git-release-four-tier-moerizz.vercel.app`, plus `sparkscribe-git-release-auth-moerizz.vercel.app`
  for this release's Preview.

## Configuration
| Setting | Where | Value |
|---|---|---|
| Site URL | Supabase → Auth → URL Configuration | `https://www.spark-scribe.com` |
| Redirect URLs | same | `https://www.spark-scribe.com/**`, `https://sparkscribe-moerizz.vercel.app/**`, and for Preview testing `https://sparkscribe-git-release-auth-moerizz.vercel.app/**`, `https://sparkscribe-git-release-four-tier-moerizz.vercel.app/**` |
| Email confirmation | Supabase → Auth → Providers → Email | on (`mailer_autoconfirm: false`) |
| SMTP | Supabase → Auth → Emails → SMTP | Resend (`EMAIL-SETUP.md`) |
| CAPTCHA | Supabase → Auth → Attack Protection | Turnstile; **turn on only after Production serves the Turnstile build** (`RELEASE.md`) |
| `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Vercel | public by design |
| `VITE_TURNSTILE_SITE_KEY` | Vercel (Config) | public Site Key |

No secret (Turnstile Secret Key, Resend API key / SMTP password, Supabase service-role key) is in this repository,
the browser bundle, or Vercel's public variables.

## Code map
| File | Role |
|---|---|
| `src/pages/auth.js` + `auth.html` | sign in / sign up / forgot / new password; messages; Turnstile |
| `src/pages/callback.js` + `auth/callback.html` | all links: `?code=` (PKCE) and `#token_hash=` (button first) |
| `src/lib/recovery.js` | reset-session rules (`recoveryAge`, `isFreshRecovery`, `guardRecovery`, `endSession`) |
| `src/lib/account.js` | `safeNext`, `getUser`, `requireUser`, account menu (runs the reset guard) |
| `src/lib/captcha.js` | Turnstile |
| `src/lib/supabase.js` | the client; `isolatedClient()` for confirmations |
| `server/http.js` | API token check; refuses reset sessions |
| `scripts/build-email-templates.mjs` | email templates and `public/email/sparkscribe-mark.png` usage |
